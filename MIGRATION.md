# Перенос установки на другую VPS

Штатный file backup предназначен для проверяемого восстановления файлов на том
же сервере и не содержит PostgreSQL или Redis. Для переноса и disaster recovery
используйте отдельный migration package из раздела `Перенос на другой VPS`.
Он сохраняет:

- согласованный логический дамп PostgreSQL;
- Redis вместе с незавершенными корзинами и временными данными;
- `state`, секреты, uploads, локальные data и готовый кабинет;
- оба Git-репозитория, включая локальные изменения;
- полные SHA бота и кабинета;
- точные Docker-образы бота, PostgreSQL и Redis со старой VPS;
- Caddy snippets и контрольные суммы всех файлов.

Архив содержит секреты. Храните его с правами `600`, передавайте только по
SSH/SCP и удалите после проверки новой VPS.

## Подготовка

1. Новая VPS должна использовать Ubuntu 24.04 и ту же архитектуру CPU.
2. Откройте порты `80` и `443` на новой VPS.
3. Заранее уменьшите TTL DNS-записей доменов.
4. Скопируйте этот installer на новую VPS вне `/opt/bot-stack`, например в
   `/root/installer`, но не выполняйте полную установку.
5. Желательно сначала провести тестовый экспорт и импорт, затем повторить
   финальный экспорт перед переключением.

После проверки пробного импорта выберите `Удалить тестовый импорт`. Installer
удалит только ресурсы незавершенного переноса, после чего можно загрузить
финальный пакет.

## 1. Экспорт на старой VPS

Запустите:

```bash
sudo bash bot-menu.sh
```

Выберите:

```text
Перенос на другой VPS -> Создать пакет переноса
```

Для пробного переноса ответьте `n` на вопрос о финальном экспорте. После
создания пакета старый бот снова запустится.

Для реального переключения выберите финальный экспорт и ответьте `y`. Бот
останется остановленным, поэтому база после дампа больше не изменится. Redis
будет запущен обратно, но без бота он не получает новые данные.

В результате появятся два файла:

```text
/root/bedolaga-migration-YYYYMMDD-HHMMSS.tar.gz
/root/bedolaga-migration-YYYYMMDD-HHMMSS.tar.gz.sha256
```

Передайте оба файла на новую VPS, например:

```bash
scp /root/bedolaga-migration-* root@NEW_VPS_IP:/root/
```

## 2. Импорт на новой VPS

Запустите тот же installer и выберите:

```text
Перенос на другой VPS -> Импортировать пакет
```

Импорт автоматически:

1. проверит внешний SHA-256 и контрольные суммы содержимого;
2. установит Docker, Compose и Caddy;
3. восстановит проект в прежний `PROJECT_ROOT`;
4. проверит точные Git SHA;
5. загрузит точные Docker-образы;
6. восстановит PostgreSQL и Redis;
7. установит конфигурацию Caddy;
8. оставит весь стек остановленным до финального переключения.

Импорт разрешен только в пустой `PROJECT_ROOT`. Это защищает существующую
установку от случайной перезаписи.

## 3. Переключение

1. Убедитесь, что старый бот остановлен.
2. Измените DNS A/AAAA обоих доменов на IP новой VPS.
3. Убедитесь, что старые AAAA-записи не ведут на прежний сервер.
4. Выберите на новой VPS:

```text
Перенос на другой VPS -> Активировать перенесенный проект
```

5. Введите `ACTIVATE`.

Installer запустит точные перенесенные образы, зарегистрирует Telegram webhook
на текущий URL и выполнит health checks. Не запускайте старого бота после
успешной активации.

## Проверка

После активации проверьте:

- `Обслуживание -> Статус`;
- `Обслуживание -> Диагностика`;
- вход существующего пользователя в кабинет;
- количество пользователей, подписок и платежей;
- загрузку старых файлов из `/uploads/`;
- создание тестовой подписки или другого безопасного действия;
- Telegram webhook и callbacks платежной системы/Remnawave.

Старую VPS не удаляйте несколько дней. Держите бота на ней остановленным до
полного подтверждения работы новой установки.
